# ADR-0003: Windows named pipe для mpv использует overlapped I/O

- Статус: `ACCEPTED`
- Дата: 2026-08-05

## Контекст

Этап 4 добавляет долгоживущий адаптер `MpvPlayerAdapter`: он одновременно ждёт события mpv и отправляет команды JSON IPC. На Windows обычный блокирующий `ReadFile`/`RandomAccessFile.read()` на том же named pipe не позволяет надёжно записывать новую команду, пока поток ждёт событие. Это проявилось в реальном прогоне: первый `observe_property` не получал ответа.

Документация mpv отдельно предупреждает, что Windows-клиенту JSON IPC нужен внешний код с overlapped I/O для одновременной записи команд и приёма ответов/событий.

## Рассмотренные варианты

1. Синхронный `RandomAccessFile` без непрерывного чтения событий.
2. Отдельное соединение pipe для команд и ещё одно для событий.
3. Один pipe с Windows overlapped I/O для каждой операции чтения и записи.

## Решение

Выбран вариант 3. `MpvIpcClient` открывает локальный pipe с `FILE_FLAG_OVERLAPPED`; каждое чтение и запись получает собственные `OVERLAPPED` и event handle. Буферы передаются JNA как удерживаемый `Memory`, а не Java `byte[]`, поскольку native-операция завершается после возврата из JNA-вызова. Ответы сопоставляются по возрастающему `request_id`; события передаются слушателям отдельно.

Адаптер создаёт уникальный pipe на запуск, ждёт соединение не более 5 секунд, держит карту ожидающих запросов и ограничивает обычные команды 3 секундами, а загрузку файла — 15 секундами. Разрыв pipe приводит к контролируемому `FAILED`, если остановка не была запрошена приложением.

## Последствия и риски

- `screenpilot-player-mpv` зависит от зафиксированных JNA/JNA-platform `5.17.0`; это Windows-специфичный адаптер mpv, а доменный модуль от JNA не зависит.
- Все native handle (`HANDLE`, event, pipe) явно закрываются. `CancelIoEx` отменяет ожидающее I/O при штатном завершении.
- Реальный интеграционный тест использует `--vo=null --ao=null`, поэтому не меняет дисплей, аудиоустройство или параметры Windows.
- Производительность чтения будет дополнительно профилироваться на длительном видео в этапах UI/приёмки; текущий P0-путь проверен на реальном mpv.

## Проверки

```powershell
.\gradlew.bat :screenpilot-player-mpv:test
.\gradlew.bat :screenpilot-player-mpv:integrationTest
```

`MpvPlayerAdapterIntegrationTest` на Windows запускает фактический `mpv.exe`, устанавливает IPC, ждёт `file-loaded`, выполняет pause, seek, play и stop. У него `--vo=null --ao=null`, поэтому физический HDMI-экран и звук для него не нужны.
