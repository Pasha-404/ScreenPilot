# ScreenPilot — функциональные требования

## 1. Назначение

Разработать Windows-приложение для воспроизведения видео на внешнем телевизоре или мониторе, подключённом к ноутбуку по HDMI.

Приложение должно автоматически обнаруживать внешний экран, позволять выбрать его разрешение и частоту обновления, выводить на него видео во весь экран и оставлять на экране ноутбука только панель управления воспроизведением.

## 2. Основные данные проекта

- Название: `ScreenPilot`
- Репозиторий: `ScreenPilot`
- Package: `ru.pavelkuzmin.screenpilot`
- Платформы: Windows 10 и Windows 11
- Основная среда тестирования: Windows 10
- Язык разработки: Java
- Предпочтительный UI: JavaFX
- Управление Windows-дисплеями: JNA и Windows Display Configuration API
- Видеодвижок: VLCJ/libVLC либо другое обоснованное решение на базе FFmpeg/mpv
- Сборка: Gradle
- Установка: Windows installer
- Установщик должен включать Java Runtime и необходимые нативные библиотеки. Пользователь не должен отдельно устанавливать Java или VLC.

## 3. Макет интерфейса

Рядом с настоящим документом находится файл:

`screen.png`

Макет используется только для общего ознакомления с предполагаемой компоновкой и визуальным стилем.

Не требуется точное воспроизведение макета. Функциональные требования настоящего документа имеют приоритет. Расположение, размеры и внешний вид элементов могут быть изменены, если это делает интерфейс проще и удобнее.

На экране ноутбука не должно быть живого предпросмотра видео.

## 4. Подключение внешнего экрана

Приложение должно:

1. Обнаруживать подключённые внешние телевизоры и мониторы.
2. Показывать список внешних экранов, если их подключено несколько.
3. Позволять выбрать один экран для воспроизведения.
4. Одновременно выводить видео только на один выбранный внешний экран.
5. По возможности определять:
   - название устройства;
   - производителя и модель;
   - тип подключения;
   - поддерживаемые разрешения;
   - поддерживаемые частоты обновления;
   - наличие HDR;
   - наличие связанного HDMI-аудиоустройства.
6. Не изменять разрешение встроенного экрана ноутбука.

Если экран уже работает в режиме расширенного рабочего стола, конфигурацию менять не требуется.

Если экран отключён или работает в режиме дублирования, приложение должно предложить включить режим расширенного рабочего стола.

Перед изменением конфигурации экранов необходимо сохранить исходное состояние. После завершения работы приложения или остановки вывода исходная конфигурация должна быть восстановлена.

## 5. Разрешение и частота обновления

Для выбранного внешнего экрана необходимо показывать:

- список поддерживаемых разрешений;
- список частот обновления для выбранного разрешения;
- рекомендуемый режим;
- автоматический выбор режима.

По умолчанию используется автоматический режим.

Автоматический режим должен учитывать:

- разрешение видео;
- частоту кадров видео;
- поддерживаемые режимы внешнего экрана.

Желательное соответствие:

- 23,976/24 FPS → 24, 48 или 60 Гц;
- 25 FPS → 50 Гц;
- 29,97/30 FPS → 60 Гц;
- 50 FPS → 50 Гц;
- 59,94/60 FPS → 60 Гц.

Пользователь должен иметь возможность вручную выбрать разрешение и частоту.

Основной список должен содержать только режимы, подтверждённые внешним экраном и драйвером.

Допускается отдельный экспериментальный ввод произвольного режима. При невозможности применить режим приложение должно автоматически вернуть предыдущие параметры.

## 6. Воспроизведение видео

Приложение должно поддерживать обычные видеофайлы распространённых форматов, включая:

- MKV;
- MP4;
- AVI;
- MOV;
- MPEG-TS;
- WebM.

Необходима поддержка распространённых кодеков, включая:

- H.264/AVC;
- H.265/HEVC;
- MPEG-2;
- VP9;
- AV1 — при поддержке используемого видеодвижка.

DVD, Blu-ray и структуры дисков не поддерживаются.

Видео должно декодироваться один раз и выводиться только на внешний экран. На ноутбуке не должно быть второго видеопотока или живого предпросмотра.

На внешнем экране видео должно открываться:

- в отдельном окне без рамки;
- во весь экран;
- поверх панели задач и других окон;
- на выбранном внешнем дисплее.

Перед началом воспроизведения допускается показывать на внешнем экране чёрный фон.

## 7. Масштабирование

Пользователь должен выбирать режим отображения:

- `Вписать` — показать всё изображение с возможными чёрными полосами;
- `Заполнить` — заполнить весь экран с возможным обрезанием;
- `1:1` — показывать видео в исходном размере без масштабирования.

Режим по умолчанию: `Вписать`.

Приложение не должно искажать пропорции изображения.

## 8. Панель управления на ноутбуке

На ноутбуке необходимо показывать:

- имя текущего файла;
- формат контейнера;
- видеокодек;
- разрешение видео;
- частоту кадров;
- длительность;
- текущую позицию;
- аудиокодек и выбранную дорожку;
- состояние субтитров;
- выбранный внешний экран;
- выбранное разрешение и частоту;
- состояние воспроизведения.

Элементы управления:

- воспроизведение;
- пауза;
- остановка;
- переход к предыдущему файлу;
- переход к следующему файлу;
- перемотка назад;
- перемотка вперёд;
- шкала воспроизведения;
- громкость;
- отключение звука;
- выбор аудиодорожки;
- выбор субтитров;
- выбор внешнего экрана;
- выбор разрешения и частоты;
- остановка вывода на внешний экран.

Регулировка скорости воспроизведения не требуется.

Переход к точному таймкоду не обязателен.

## 9. Управление с клавиатуры

Горячие клавиши должны работать, когда активно окно ScreenPilot:

- `Пробел` — воспроизведение/пауза;
- `←` — назад на 10 секунд;
- `→` — вперёд на 10 секунд;
- `Ctrl + ←` — назад на 60 секунд;
- `Ctrl + →` — вперёд на 60 секунд;
- `↑` — увеличить громкость;
- `↓` — уменьшить громкость;
- `Esc` — остановить полноэкранный вывод;
- `Ctrl + O` — открыть видеофайл.

При перемотке позиция не должна становиться меньше нуля или превышать длительность файла.

## 10. Плейлист

Приложение должно поддерживать плейлист.

Необходимо реализовать:

- добавление одного или нескольких файлов;
- добавление файлов перетаскиванием в окно;
- удаление элементов;
- изменение порядка;
- запуск выбранного элемента;
- переход к предыдущему и следующему файлу;
- автоматический запуск следующего файла;
- отображение длительности и основных параметров файлов.

После завершения последнего файла воспроизведение останавливается.

Зацикливание плейлиста в первой версии не требуется.

## 11. Звук

По умолчанию приложение должно попытаться выбрать HDMI-аудиоустройство, связанное с выбранным внешним экраном.

Пользователь должен иметь возможность вручную выбрать:

- HDMI-аудиоустройство;
- динамики ноутбука;
- наушники;
- другое доступное устройство Windows.

Если у внешнего монитора отсутствует аудиоустройство, приложение должно оставить текущее устройство вывода и показать понятное уведомление.

Необходимо поддерживать:

- выбор встроенной аудиодорожки;
- изменение громкости;
- отключение звука;
- стерео и многоканальный звук, насколько это поддерживает оборудование и видеодвижок.

## 12. Субтитры

Поддержать:

- встроенные субтитры;
- внешние файлы `.srt`;
- внешние файлы `.ass`;
- внешние файлы `.ssa`;
- включение и отключение;
- выбор дорожки;
- ручное подключение внешнего файла.

Расширенные настройки шрифта, цвета и позиции в первой версии не требуются.

## 13. HDR и 10-битное видео

Первая версия должна поддерживать декодирование 10-битного видео, включая HEVC Main 10.

HDR10-вывод является приоритетным требованием.

HDR должен использоваться, если его поддерживают:

- видео;
- видеокарта;
- драйвер;
- HDMI-подключение;
- выбранное разрешение и частота;
- внешний экран;
- настройки Windows.

Если HDR недоступен, HDR-видео должно воспроизводиться на SDR-экране с корректным преобразованием цветов или tone mapping, насколько это поддерживает выбранный видеодвижок.

Отсутствие HDR не должно приводить к отказу воспроизведения.

## 14. Сохранение состояния

Приложение должно сохранять:

- последнюю выбранную папку;
- последний выбранный внешний экран;
- последнее разрешение;
- последнюю частоту;
- режим масштабирования;
- выбранное устройство звука;
- уровень громкости;
- состояние автоматического выбора режима;
- позиции просмотра видеофайлов.

Позицию просмотра следует идентифицировать по полному пути файла и дополнительным параметрам файла, чтобы не путать разные файлы с одинаковым названием.

При повторном открытии незавершённого файла приложение должно предложить:

- продолжить с сохранённой позиции;
- начать сначала.

Отдельные профили для каждого телевизора или монитора не требуются. Сохраняются последние общие настройки.

## 15. Отключение HDMI

Если выбранный внешний экран отключён во время воспроизведения:

1. Видео ставится на паузу.
2. Внешнее полноэкранное окно закрывается.
3. Панель управления остаётся доступной.
4. Пользователю показывается сообщение об отключении устройства.
5. После повторного подключения воспроизведение автоматически не продолжается.
6. Пользователь самостоятельно выбирает экран и продолжает воспроизведение.

Приложение не должно аварийно завершаться при отключении кабеля.

## 16. Ошибки

Необходимо обрабатывать:

- отсутствие внешнего экрана;
- исчезновение выбранного экрана;
- неподдерживаемое разрешение;
- ошибку изменения конфигурации Windows;
- невозможность открыть видео;
- отсутствие необходимого кодека;
- ошибку аппаратного декодирования;
- отсутствие HDMI-аудиоустройства;
- повреждённый видеофайл;
- невозможность восстановить исходную конфигурацию экранов.

Сообщения должны быть понятны пользователю и содержать возможное действие.

При ошибке аппаратного декодирования приложение должно попытаться использовать программное декодирование.

## 17. Интерфейс

Интерфейс должен быть:

- тёмным;
- современным;
- без лишних экранов;
- рассчитанным на управление с ноутбука;
- удобным при разрешении 1920×1080;
- пригодным для меньших экранов ноутбуков;
- масштабируемым при системном DPI 100–200%.

Основные элементы управления должны быть доступны на одном экране без необходимости постоянно переходить между разделами.

Текущая позиция, шкала времени, пауза и перемотка должны быть наиболее заметными элементами.

## 18. Ограничения первой версии

В первую версию не входят:

- беспроводная передача видео;
- Miracast;
- Chromecast;
- трансляция по локальной сети;
- управление со смартфона;
- DVD и Blu-ray;
- воспроизведение интернет-потоков;
- изменение скорости воспроизведения;
- редактирование видео;
- захват экрана;
- одновременный вывод на несколько внешних экранов;
- живой предпросмотр на ноутбуке.

## 19. Установщик

Необходимо подготовить Windows-установщик.

Установщик должен:

- работать на Windows 10/11 x64;
- устанавливать приложение в стандартную папку;
- создавать ярлык в меню «Пуск»;
- по выбору создавать ярлык на рабочем столе;
- включать необходимые Java Runtime и нативные библиотеки;
- поддерживать корректное удаление;
- не требовать установленного VLC или Java.

Предпочтительно использовать `jpackage`.

## 20. Критерии приёмки MVP

MVP считается готовым, если:

1. Приложение запускается на Windows 10 без отдельно установленной Java.
2. Обнаруживает подключённый по HDMI монитор.
3. Показывает доступные разрешения и частоты.
4. Не изменяет разрешение экрана ноутбука.
5. При необходимости включает расширенный режим.
6. Запускает MKV или MP4 с H.264 и H.265 на внешнем экране.
7. На ноутбуке отсутствует живой предпросмотр.
8. Работают пауза, шкала времени и перемотка стрелками.
9. Работает выбор внешнего экрана.
10. Работает выбор HDMI-звука или динамиков ноутбука.
11. Работает плейлист.
12. Сохраняется позиция просмотра.
13. При отключении HDMI воспроизведение ставится на паузу.
14. После завершения восстанавливается исходная конфигурация экранов.
15. 10-битный HEVC-файл воспроизводится без ошибки.
16. HDR-видео воспроизводится хотя бы с корректным SDR-преобразованием, если тестовый монитор не поддерживает HDR.

## 21. Порядок реализации

Рекомендуемый порядок:

1. Создать каркас JavaFX-приложения.
2. Реализовать обнаружение экранов и их параметров.
3. Реализовать выбор внешнего экрана.
4. Реализовать отдельное полноэкранное окно.
5. Подключить видеодвижок.
6. Реализовать базовое воспроизведение одного файла.
7. Добавить панель управления и горячие клавиши.
8. Добавить выбор разрешения и частоты.
9. Реализовать сохранение и восстановление конфигурации экранов.
10. Добавить выбор звукового устройства.
11. Добавить плейлист.
12. Добавить сохранение позиции.
13. Добавить субтитры.
14. Проверить 10-битное видео и HDR/SDR.
15. Реализовать обработку отключения HDMI.
16. Собрать Windows-установщик.
17. Добавить автоматические тесты для логики, не зависящей от оборудования.
18. Подготовить ручной чек-лист тестирования дисплеев, HDMI и звука.

Перед началом разработки необходимо проверить выбранный видеодвижок небольшим техническим прототипом:

- H.265/HEVC;
- HEVC Main 10;
- аппаратное декодирование;
- отдельное окно на выбранном дисплее;
- HDR или SDR tone mapping;
- выбор звукового устройства.

Если VLCJ/libVLC создаёт существенные ограничения для HDR, выбора аудиоустройства или стабильного вывода на конкретный экран, допускается выбрать mpv или другой движок. Решение следует зафиксировать в README.
