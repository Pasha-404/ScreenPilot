# ScreenPilot — техническое задание на разработку MVP

Статус: версия 1.0, готово к реализации после прохождения технического прототипа.

Дата: 4 августа 2026 года.

Исполнитель разработки: модель Terra.

Исходные материалы:

- [ScreenPilot_FT.md](ScreenPilot_FT.md) — исходные функциональные требования;
- [screen.png](screen.png) — ориентир по компоновке и визуальному стилю.

Если это ТЗ расходится с исходными функциональными требованиями, приоритет имеет это ТЗ. Исключение — явное последующее решение владельца проекта.

## 1. Цель документа

Документ должен позволить Terra разработать ScreenPilot без самостоятельного определения продуктовых границ и без скрытых технических предположений.

ScreenPilot — локальное Windows-приложение, которое:

1. Обнаруживает внешний экран, в первую очередь подключённый по HDMI.
2. Показывает панель управления на экране ноутбука.
3. Запускает видео в отдельном полноэкранном окне только на выбранном внешнем экране.
4. Управляет разрешением и частотой обновления внешнего экрана, не меняя параметры встроенного экрана ноутбука.
5. Направляет звук на выбранное пользователем устройство, по возможности автоматически предлагая связанный HDMI-выход.
6. Сохраняет настройки и позиции просмотра.
7. Безопасно реагирует на отключение экрана и восстанавливает исходную конфигурацию Windows после временных изменений.

Первая версия предназначена прежде всего для личного использования владельцем проекта. Архитектура не должна препятствовать дальнейшему публичному распространению, но коммерческая поставка, автоматическое обновление и публикация в Microsoft Store в MVP не входят.

## 2. Подтверждённые решения

### 2.1. Платформа

- Целевая ОС: Windows 10 и Windows 11 x64.
- Минимальная проверяемая ОС: Windows 10 Pro 22H2, сборка 19045, x64.
- Приложение устанавливается для текущего пользователя.
- Обычная установка и работа не требуют прав администратора.
- Пользователь не устанавливает Java, VLC, mpv, FFmpeg или кодеки отдельно.

### 2.2. Экраны и подключения

- Поддержка HDMI обязательна и входит в критерии приёмки.
- DisplayPort, USB-C, док-станции и другие внешние подключения поддерживаются, если Windows показывает их через тот же Display Configuration API и для них не нужна отдельная логика.
- Для подключений, отличных от HDMI, в MVP действует режим best effort: они отображаются в списке и могут использоваться, но не входят в обязательную аппаратную приёмку.
- Встроенный экран ноутбука нельзя выбирать как целевой экран вывода.

### 2.3. Изменения конфигурации Windows

- Переход из режима «Дублировать» или из отключённого состояния в режим «Расширить» выполняется только после явного подтверждения пользователя.
- Разрешение и частота выбранного внешнего экрана могут меняться автоматически и временно.
- ScreenPilot не меняет системное аудиоустройство Windows по умолчанию. Маршрутизация звука действует только для процесса видеоплеера.
- ScreenPilot не включает системный HDR автоматически.
- Перед первым изменением дисплеев в сессии сохраняется исходная конфигурация.
- При остановке вывода и штатном завершении исходная конфигурация восстанавливается автоматически.
- После аварии восстановление предлагается при следующем запуске по сохранённому журналу.

### 2.4. HDR

- Для MVP обязательно воспроизведение 10-битного HEVC Main 10.
- Для MVP обязательно корректное преобразование HDR-видео в SDR средствами видеодвижка.
- Настоящий HDR-вывод на HDR-экран — задача приоритета P1 после MVP. Его можно включить в MVP только при успешном прототипе без усложнения основной архитектуры.
- Недоступность HDR никогда не должна блокировать обычное воспроизведение.

### 2.5. Видеодвижок

Основной кандидат для MVP — отдельный процесс `mpv.exe`, управляемый из Java через локальный JSON IPC по именованному каналу Windows.

Это решение должно быть подтверждено прототипом до создания основного интерфейса. Если прототип не проходит обязательные проверки, Terra останавливает основную разработку, фиксирует результаты в ADR и предлагает один из вариантов:

1. libmpv через JNA;
2. VLCJ/libVLC;
3. другой локальный движок на базе FFmpeg с обоснованием стоимости и рисков.

Самостоятельно менять видеодвижок после начала основной реализации запрещено.

## 3. Эталонная минимальная конфигурация

Приложение должно пройти приёмку на ноутбуке со следующей конфигурацией или на эквивалентном по возможностям оборудовании:

| Компонент | Значение |
|---|---|
| Производитель и модель | HONOR BMH-WCX9 |
| ОС | Windows 10 Pro 22H2 x64, сборка 19045 |
| Процессор | AMD Ryzen 5 5500U, 6 ядер / 12 потоков |
| ОЗУ | 16 ГБ |
| Графика | AMD Radeon Graphics |
| Версия проверенного драйвера | 31.0.12046.15003 или более новая совместимая |
| Встроенный экран | 1920×1080, 60 Гц |
| Обязательный внешний экран | HDMI-монитор или телевизор минимум 1920×1080@60 Гц |

Во время подготовки ТЗ внешний экран не был подключён. Фактические EDID, доступные частоты, HDMI-аудио и HDR необходимо проверить на этапе аппаратного прототипа.

Минимальные эксплуатационные условия:

- минимум 4 ГБ свободного места на диске для приложения, журналов и временных файлов;
- актуальный для ноутбука драйвер графики;
- локальный интерактивный сеанс Windows, не RDP;
- доступ на чтение к открываемым видеофайлам;
- право текущего пользователя записывать в `%LOCALAPPDATA%\ScreenPilot`.

## 4. Термины

| Термин | Определение |
|---|---|
| Встроенный экран | Экран ноутбука, определённый Windows как внутренний дисплей. |
| Внешний экран | Активный или доступный display target, не относящийся к встроенной панели. |
| Целевой экран | Один внешний экран, выбранный пользователем для видео. |
| Режим экрана | Набор: ширина, высота, рациональная частота обновления, тип развёртки и глубина цвета. |
| Топология | Состав активных дисплеев, их режим «Расширить/Дублировать» и расположение в виртуальном рабочем столе. |
| Сессия вывода | Период от подготовки внешнего экрана до команды «Остановить вывод» или завершения приложения. |
| Исходный снимок | Конфигурация дисплеев до первого изменения ScreenPilot в текущей сессии. |
| Восстановление | Возврат Windows к исходному снимку или к последней сохранённой системной конфигурации. |
| Основной процесс | JavaFX-приложение ScreenPilot. |
| Процесс плеера | Управляемый дочерний процесс `mpv.exe`. |

## 5. Приоритеты требований

- `P0` — обязательно для MVP и блокирует приёмку.
- `P1` — желательно после стабильного MVP; не блокирует первую поставку.
- `P2` — будущее развитие.

Все требования без явного приоритета считаются `P0`.

## 6. Технический стек

### 6.1. Обязательная база

| Назначение | Решение |
|---|---|
| Язык | Java 21 LTS |
| UI | JavaFX 21, последняя совместимая патч-версия |
| Сборка | Gradle Wrapper, зафиксированная стабильная версия, совместимая с Java 21 |
| JavaFX Gradle plugin | `org.openjfx.javafxplugin` |
| Доступ к Win32 | JNA и `jna-platform` |
| Видеодвижок | поставляемый вместе с приложением `mpv.exe` после прохождения прототипа |
| IPC | mpv JSON IPC через уникальный именованный канал Windows |
| JSON | Jackson Databind |
| Логирование | SLF4J + Logback |
| Тесты | JUnit Jupiter, AssertJ; Mockito только для внешних границ |
| Установщик | `jpackage`, тип `exe`, установка для текущего пользователя |

Точные версии зависимостей Terra фиксирует в `gradle/libs.versions.toml`. Динамические версии вида `+`, `latest.release` и незакреплённые snapshot-сборки запрещены.

### 6.2. Правила выбора зависимостей

1. Сначала использовать JDK и JavaFX API.
2. Новая библиотека допускается, если она сокращает риск или заметный объём собственной инфраструктуры.
3. Для каждой нативной зависимости указать версию, источник, лицензию и SHA-256.
4. Приложение не скачивает исполняемые файлы или библиотеки при первом запуске.
5. Публичная поставка потребует отдельной лицензионной проверки mpv и его сборки; для личного MVP достаточно положить тексты лицензий в установщик и зафиксировать источник бинарников.

### 6.3. Решения, намеренно не используемые в MVP

- JavaFX MediaPlayer как основной движок;
- передача декодированных видеокадров в JavaFX через `PixelBuffer`;
- встраивание видеоповерхности в основное окно;
- Electron, webview или локальный веб-сервер;
- база данных;
- Spring Framework;
- сетевые API и телеметрия;
- автоматическое изменение системного аудиоустройства Windows.

### 7.2. Модули

#### `screenpilot-domain`

Содержит:

- модели дисплеев, режимов, медиафайлов, дорожек, плейлиста и позиции просмотра;
- алгоритм выбора разрешения и частоты;
- состояния воспроизведения и сессии вывода;
- правила переходов между состояниями;
- интерфейсы портов;
- ошибки предметной области.

Не содержит JavaFX, JNA и классов конкретного JSON-парсера.

#### `screenpilot-player-mpv`

Содержит:

- запуск и завершение mpv;
- клиент JSON IPC;
- преобразование mpv-событий и свойств в доменные события;
- управление воспроизведением, дорожками, субтитрами, масштабированием и аудиовыходом;
- получение метаданных без живого предпросмотра;
- обнаружение сбоя аппаратного декодирования и программный fallback.

#### `screenpilot-platform-windows`

Содержит:

- JNA-привязки к Display Configuration API, GDI User32 и Kernel32;
- обнаружение дисплеев и типов подключения;
- перечисление и временное применение режимов;
- сохранение и восстановление топологии;
- размещение окна mpv на целевом мониторе;
- Windows Job Object для дочернего процесса;
- периодическое обнаружение изменений дисплеев.

#### `screenpilot-persistence`

Содержит:

- JSON-хранилище настроек;
- хранилище позиций просмотра;
- журнал восстановления дисплеев;
- атомарную запись файлов;
- миграцию схемы данных.

#### `screenpilot-app`

Содержит:

- точку входа;
- JavaFX FXML/CSS и контроллеры;
- application services и координацию use case;
- отображение состояний и ошибок;
- сборку зависимостей;
- обработку закрытия приложения.

### 7.3. Направление зависимостей

```text
screenpilot-app
  ├─> screenpilot-domain
  ├─> screenpilot-player-mpv ─> screenpilot-domain
  ├─> screenpilot-platform-windows ─> screenpilot-domain
  └─> screenpilot-persistence ─> screenpilot-domain
```

Циклические зависимости между модулями запрещены.

### 7.4. Потоки выполнения

| Поток | Назначение |
|---|---|
| JavaFX Application Thread | Только построение и изменение UI. |
| `application-serial` | Последовательная обработка команд и переходов состояния. |
| `mpv-ipc-reader` | Чтение строк JSON IPC и публикация событий. |
| `display-poller` | Проверка топологии раз в 1 секунду. |
| `media-probe` | Не более одного параллельного анализа файла. |
| `io-writer` | Запись настроек, resume и журналов восстановления. |

Запрещено выполнять Win32-вызовы, ожидание IPC, анализ медиа и файловые операции на JavaFX Application Thread.

События от фоновых потоков сначала поступают в `application-serial`, после изменения модели UI обновляется через `Platform.runLater`.

## 9. Доменные модели

### 9.1. Дисплей

`DisplayInfo` содержит:

- `DisplayId id`;
- `String friendlyName`;
- `String manufacturer`;
- `String model`;
- `ConnectionType connectionType`;
- `boolean internal`;
- `boolean active`;
- `boolean primary`;
- `boolean targetAvailable`;
- `String gdiDeviceName` вида `\\.\DISPLAYn`;
- координаты и размер в виртуальном рабочем столе;
- текущий режим;
- предпочтительный режим;
- список подтверждённых режимов;
- сведения о поддержке Advanced Color/HDR, если API их возвращает;
- идентификаторы адаптера и target для повторных Win32-вызовов.

`DisplayId` строится из доступных стабильных признаков в следующем порядке:

1. `monitorDevicePath` + EDID manufacturer/product;
2. `monitorDevicePath`;
3. `adapterLuid` + target ID как временный fallback.

Последний вариант нельзя считать стабильным между перезагрузками. Если сохранённый экран не найден однозначно, приложение требует повторного выбора.

### 9.2. Режим дисплея

`DisplayMode` содержит:

- ширину и высоту в физических пикселях;
- частоту как рациональное число `numerator/denominator` и отображаемое десятичное значение;
- признак чересстрочной развёртки;
- bits per pixel, если доступны;
- признак preferred/native;
- исходный `DEVMODEW` или достаточные данные для его безопасного восстановления;
- источник подтверждения режима.

Режимы сравниваются по рациональной частоте. Нельзя сводить 59,94 Гц к 60 Гц или 23,976 FPS к 24 FPS во внутренней модели.

### 9.3. Медиа

`MediaInfo` содержит:

- абсолютный нормализованный путь;
- отображаемое имя файла;
- контейнер;
- длительность;
- видеокодек и профиль;
- ширину и высоту;
- рациональную частоту кадров;
- признак interlaced;
- bit depth;
- цветовое пространство и transfer characteristics, если доступны;
- признак HDR;
- список аудиодорожек;
- список субтитров;
- текущие выбранные дорожки.

Неизвестное значение представляется явно как `Optional`/`UNKNOWN`, а не нулём или пустой строкой.

### 9.4. Отпечаток файла

`MediaFingerprint` включает:

- нормализованный абсолютный путь;
- размер файла;
- время последнего изменения с точностью файловой системы.

Хешировать весь видеофайл в MVP не нужно.

## 10. Машины состояний

### 10.1. Сессия вывода

Состояния:

```text
NO_TARGET
TARGET_READY
PREPARING_DISPLAY
OUTPUT_IDLE
OUTPUT_ACTIVE
RESTORING_DISPLAY
OUTPUT_ERROR
```

Основные переходы:

| Исходное состояние | Событие | Новое состояние | Действие |
|---|---|---|---|
| `NO_TARGET` | найден и выбран экран | `TARGET_READY` | загрузить режимы и аудиовыходы |
| `TARGET_READY` | команда запуска | `PREPARING_DISPLAY` | сохранить снимок, проверить топологию и режим |
| `PREPARING_DISPLAY` | подготовка успешна | `OUTPUT_IDLE` | открыть чёрное окно mpv на целевом экране |
| `OUTPUT_IDLE` | файл загружен | `OUTPUT_ACTIVE` | запустить или оставить на паузе согласно команде |
| `OUTPUT_ACTIVE` | отключение цели | `OUTPUT_ERROR` | пауза, закрытие окна, уведомление |
| любое активное | «Остановить вывод» | `RESTORING_DISPLAY` | завершить mpv и восстановить снимок |
| `RESTORING_DISPLAY` | успех | `TARGET_READY` или `NO_TARGET` | очистить recovery journal |
| `RESTORING_DISPLAY` | ошибка | `OUTPUT_ERROR` | сохранить журнал и показать ручное действие |

Повторная команда запуска, пока выполняется `PREPARING_DISPLAY` или `RESTORING_DISPLAY`, игнорируется с блокировкой соответствующей кнопки.

### 10.2. Плеер

Состояния:

```text
STOPPED -> STARTING -> IDLE -> LOADING -> PLAYING <-> PAUSED
                                   \-> FAILED
PLAYING/PAUSED -> IDLE
любое -> STOPPING -> STOPPED
```

`FAILED` не означает завершение всего приложения. UI остаётся доступным, а пользователь может повторить запуск, выбрать другой файл или другое устройство.

### 10.3. Единственный источник истины

`ApplicationState` — неизменяемый снимок состояния, содержащий:

- список дисплеев и выбранный дисплей;
- доступные режимы и выбранный режим;
- состояние сессии вывода;
- состояние плеера;
- текущий медиафайл и позицию;
- плейлист;
- аудио- и субтитровые дорожки;
- выбранный аудиовыход;
- активное пользовательское сообщение.

JavaFX-контроллеры не должны хранить независимую бизнес-логику или конкурирующие копии состояния.

## 11. Подсистема дисплеев Windows

### 11.1. Обнаружение

Авторитетный источник состояния — Win32 Display Configuration API.

Алгоритм обнаружения:

1. Вызвать `GetDisplayConfigBufferSizes`.
2. Вызвать `QueryDisplayConfig` с `QDC_ALL_PATHS` и поддержкой virtual mode на Windows 10.
3. При `ERROR_INSUFFICIENT_BUFFER` повторить шаги 1–2, но не более трёх раз за один цикл.
4. Для каждого target вызвать `DisplayConfigGetDeviceInfo` с запросами:
   - `DISPLAYCONFIG_DEVICE_INFO_GET_TARGET_NAME`;
   - `DISPLAYCONFIG_DEVICE_INFO_GET_TARGET_PREFERRED_MODE`;
   - `DISPLAYCONFIG_DEVICE_INFO_GET_SOURCE_NAME`;
   - `DISPLAYCONFIG_DEVICE_INFO_GET_ADVANCED_COLOR_INFO`, если поддерживается ОС и драйвером.
5. Сопоставить source с GDI-именем `\\.\DISPLAYn`.
6. Отделить внутреннюю панель по `DISPLAYCONFIG_OUTPUT_TECHNOLOGY_INTERNAL` и дополнительным признакам target.
7. Для внешних target определить тип подключения: HDMI, DisplayPort, DVI, USB-C/adapter или unknown.
8. Отсортировать: активные HDMI, другие активные внешние, неактивные доступные.

Если friendly name отсутствует, интерфейс показывает безопасное имя вида `Внешний экран 1 (HDMI)`.

### 11.2. Отслеживание изменений

Для MVP использовать опрос раз в 1 секунду:

- вычислить хеш значимых полей текущей топологии;
- при изменении повторно обнаружить дисплеи и доступные режимы;
- опубликовать `DisplayTopologyChanged`;
- не выполнять тяжёлую работу, если хеш не изменился.

Событийное окно Win32 с `WM_DISPLAYCHANGE`/`WM_DEVICECHANGE` допускается как P1, но не нужно для MVP. Требуемая задержка обнаружения отключения — не более 2 секунд.

### 11.3. Перечисление режимов

Для выбранного активного target:

1. Получить GDI device name.
2. Перечислить режимы через `EnumDisplaySettingsExW`.
3. Сохранить только структуры `DEVMODEW`, возвращённые драйвером.
4. Исключить ширину или высоту меньше 640×480, глубину меньше 32 bpp и частоту 0 Гц.
5. Чересстрочные режимы скрыть из основного списка. Их можно показывать только в раскрываемом разделе «Совместимость».
6. Дедуплицировать по ширине, высоте, рациональной частоте и типу развёртки.
7. Пометить текущий и предпочтительный режимы.

Основной пользовательский список не принимает произвольные значения. Экспериментальный ввод произвольного режима — P1.

### 11.4. Переход к расширенному рабочему столу

Если выбранный target подключён, но не активен или работает в топологии clone:

1. Показать диалог с объяснением, что Windows временно перейдёт в режим «Расширить».
2. Кнопки: `Переключить` и `Отмена`.
3. При подтверждении сохранить исходный снимок и recovery journal.
4. Вызвать `SetDisplayConfig` с временной extended topology без `SDC_SAVE_TO_DATABASE`.
5. Дождаться новой топологии не более 10 секунд.
6. Проверить, что встроенный и выбранный внешний экраны активны и не клонируют один source.
7. При ошибке немедленно начать восстановление.

Если Windows не даёт активировать конкретный target через сохранённые paths, разрешён fallback на последнюю extended topology Windows. После fallback пользователь обязан снова выбрать экран, поскольку Windows могла активировать другой target.

### 11.5. Временное применение режима

Алгоритм:

1. Не менять встроенный дисплей и не отправлять для него новый `DEVMODEW`.
2. Проверить выбранный режим через `ChangeDisplaySettingsExW(..., CDS_TEST, ...)`.
3. При успешной проверке применить тот же `DEVMODEW` динамически без `CDS_UPDATEREGISTRY`.
4. Дождаться обновлённой топологии до 10 секунд.
5. Повторно запросить фактический режим и сравнить с запросом с допуском 0,02 Гц.
6. Если драйвер выбрал другое значение или режим не применился, восстановить предыдущий режим и показать ошибку.

При автоматическом выборе подтверждение на каждую смену не требуется. На экране ноутбука показывается неблокирующее уведомление с фактически установленным режимом.

Для будущего экспериментального режима требуется диалог подтверждения с 15-секундным обратным отсчётом. Без подтверждения выполняется rollback.

### 11.6. Снимок и восстановление

Исходный снимок создаётся один раз перед первым изменением в сессии и не перезаписывается последующими сменами частоты.

Снимок содержит:

- версию схемы;
- время и UUID сессии;
- топологию и идентификатор topology, если доступен;
- сериализуемые значения paths и modes, необходимые для `SetDisplayConfig`;
- текущие `DEVMODEW` всех активных source;
- выбранный внешний target;
- контрольную сумму содержимого.

Порядок восстановления:

1. Проверить схему, контрольную сумму и наличие целевых устройств.
2. Проверить снимок через `SetDisplayConfig` с `SDC_VALIDATE`.
3. Применить снимок через `SDC_APPLY | SDC_USE_SUPPLIED_DISPLAY_CONFIG`.
4. Если снимок устарел или невалиден, вызвать `SDC_APPLY | SDC_USE_DATABASE_CURRENT`.
5. Повторно запросить топологию и проверить ожидаемое состояние.
6. Только после подтверждённого успеха пометить recovery journal завершённым.

Если оба способа не сработали, приложение:

- не удаляет recovery journal;
- показывает инструкцию `Win + P → нужный режим`;
- предлагает открыть системные параметры дисплея;
- записывает Win32-коды в лог.

### 11.7. Аварийное восстановление

MVP не обязан восстанавливать топологию мгновенно после принудительного завершения процесса или отключения питания.

При следующем запуске:

1. Проверить незавершённый recovery journal до обычного обнаружения дисплеев.
2. Показать: `Предыдущая сессия завершилась до восстановления экранов`.
3. Предложить `Восстановить`, `Оставить как есть`, `Подробнее`.
4. `Восстановить` выполняет алгоритм 11.6.
5. `Оставить как есть` помечает запись закрытой, но сохраняет её архивную копию семь дней.

Shutdown hook выполняет best-effort остановку mpv и восстановление, но корректность не должна зависеть только от него.

## 12. Алгоритм автоматического выбора режима

Алгоритм реализуется как чистая функция и полностью покрывается параметризованными unit-тестами.

Вход:

- параметры видео;
- текущий режим target;
- предпочтительный режим target;
- подтверждённые режимы;
- пользовательские настройки auto/manual.

### 12.1. Нормализация FPS

Распознавать с допуском 0,02 FPS:

| Наблюдаемое значение | Семейство |
|---|---|
| 23,976 | 24000/1001 |
| 24 | 24/1 |
| 25 | 25/1 |
| 29,97 | 30000/1001 |
| 30 | 30/1 |
| 50 | 50/1 |
| 59,94 | 60000/1001 |
| 60 | 60/1 |

Неизвестная или переменная частота кадров не вызывает смену режима только на основании FPS.

### 12.2. Классы частот

Приоритет частоты:

1. Точное совпадение FPS или целый кратный коэффициент 2–5 с отклонением не более 0,1%.
2. Для 23,976/24 FPS допустимы 59,94/60 Гц.
3. Текущая частота, если она не хуже других кандидатов.
4. Предпочтительная частота дисплея.
5. Наибольшая подтверждённая прогрессивная частота не выше 120 Гц.

Предпочтительные соответствия:

- 23,976 → 23,976; 47,952; 59,94 Гц;
- 24 → 24; 48; 60 Гц;
- 25 → 25; 50; 100 Гц;
- 29,97 → 29,97; 59,94 Гц;
- 30 → 30; 60 Гц;
- 50 → 50; 100 Гц;
- 59,94 → 59,94; 119,88 Гц;
- 60 → 60; 120 Гц.

### 12.3. Выбор разрешения

После определения лучшего класса частоты:

1. Предпочесть preferred/native resolution, если оно доступно с частотой лучшего класса.
2. Иначе предпочесть разрешение, не меньше исходного видео по обеим осям и ближайшее к preferred.
3. Иначе предпочесть точное разрешение видео.
4. Иначе выбрать наибольшее доступное разрешение с частотой лучшего класса.
5. Не выбирать режим, который требует понижения разрешения относительно текущего, если выигрыш частоты относится только к классу 2 или ниже.

Таким образом, 1080p-видео обычно выводится в native 4K с масштабированием mpv, если телевизор поддерживает подходящую частоту в 4K. Переход с 4K на 1080p допускается, если только в 1080p доступна частота, точно кратная FPS, и пользователь включил настройку `Приоритет плавности`.

### 12.4. Результат

Алгоритм возвращает:

- выбранный режим;
- причину выбора;
- уровень уверенности `EXACT`, `COMPATIBLE`, `FALLBACK`;
- признак необходимости реального переключения.

Причина отображается во всплывающей подсказке рядом с `Автовыбор`.

## 13. Управление mpv

### 13.1. Технический профиль запуска

`mpv.exe` запускается через `ProcessBuilder` со списком отдельных аргументов. Конкатенация командной строки вручную запрещена.

Базовые параметры прототипа:

```text
--no-config
--idle=yes
--force-window=immediate
--keep-open=yes
--terminal=no
--input-default-bindings=no
--osc=no
--no-border
--ontop=yes
--vo=gpu-next
--gpu-context=d3d11
--hwdec=auto-safe
--input-ipc-server=<unique-windows-named-pipe>
--title=ScreenPilot Output <session-uuid>
```

Точный профиль фиксируется после прототипа в `docs/adr/0001-video-engine.md` и в одном классе `MpvLaunchProfile`. Не дублировать параметры по контроллерам.

Пользовательский `mpv.conf` игнорируется через `--no-config`, чтобы поведение было воспроизводимым.

### 13.2. Именованный канал

- Имя содержит случайный UUID и не принимается из пользовательского ввода.
- Канал локальный и удаляется после завершения процесса.
- Клиент делает повторные попытки подключения не дольше 5 секунд.
- Сообщения — UTF-8 JSON, по одному объекту на строку.
- Для каждой команды назначается монотонный `request_id`.
- Ожидающие ответы хранятся в `ConcurrentHashMap<Long, CompletableFuture<?>>`.
- Тайм-аут обычной команды — 3 секунды, загрузки файла — 15 секунд.
- Неизвестные события логируются на DEBUG и не завершают приложение.
- Разрыв канала переводит плеер в `FAILED`, если процесс не завершён штатно.

Минимальные команды:

- `loadfile` с режимом `replace`;
- `set_property pause`;
- `seek` absolute/exact и relative;
- `stop`;
- `quit`;
- `set_property volume`;
- `set_property mute`;
- `set_property aid`;
- `set_property sid`;
- `sub-add`;
- `set_property audio-device`;
- свойства масштабирования.

Минимальные наблюдаемые свойства:

- `pause`;
- `time-pos`;
- `duration`;
- `eof-reached`;
- `idle-active`;
- `media-title`;
- `path`;
- `file-format`;
- `video-format`;
- `video-params`;
- `container-fps` и доступный фактический FPS;
- `track-list`;
- `audio-device-list`;
- `audio-device`;
- `hwdec-current`;
- `estimated-vf-fps`;
- счётчики dropped/mistimed frames, если доступны.

### 13.3. Управление дочерним процессом

После запуска mpv назначить его Windows Job Object с `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`.

Назначение:

- mpv завершается при закрытии последнего handle Job Object;
- после аварии Java-процесса не остаётся полноэкранное окно;
- завершение не зависит только от shutdown hook.

Если Job Object создать не удалось, воспроизведение допускается, но UI показывает диагностическое предупреждение, а лог содержит Win32-код. Для релизной приёмки Job Object обязан работать на эталонном ноутбуке.

Штатное завершение:

1. Отправить `quit`.
2. Ждать до 3 секунд.
3. Вызвать `Process.destroy()`.
4. Ждать до 2 секунд.
5. Вызвать `destroyForcibly()`.
6. Закрыть IPC и Job Object handles.

### 13.4. Размещение окна

Алгоритм:

1. Подготовить внешний дисплей и получить его физические координаты в виртуальном рабочем столе.
2. Запустить mpv с уникальным title и параметрами target screen/geometry, проверенными прототипом.
3. Найти HWND окна по PID и уникальному title через `EnumWindows` и `GetWindowThreadProcessId`.
4. Проверить `GetWindowRect`.
5. При необходимости переместить окно через `SetWindowPos` на координаты target.
6. Перевести mpv в fullscreen на target.
7. Проверить, что центр окна лежит в прямоугольнике выбранного дисплея.
8. Если проверка не пройдена, закрыть окно, восстановить режим и показать ошибку. Запуск видео на встроенном экране как fallback запрещён.

До загрузки файла окно должно быть чёрным. Живой предпросмотр в JavaFX не создаётся.

Перед началом вывода основное JavaFX-окно проверяется по координатам. Если оно находится на выбранном внешнем target, приложение переносит его в видимую область встроенного экрана и сохраняет новое положение. Панель управления должна оставаться на ноутбуке даже тогда, когда пользователь ранее переместил окно на внешний монитор.

### 13.5. Аппаратное декодирование и fallback

1. Первый запуск файла использует безопасный автоматический аппаратный decode profile.
2. После загрузки записать фактическое значение `hwdec-current`.
3. При явной ошибке декодера сохранить позицию и состояние play/pause.
4. Один раз перезагрузить файл с `hwdec=no`.
5. Восстановить позицию и прежнее состояние.
6. Показать уведомление `Аппаратное декодирование недоступно — используется процессор`.
7. Повторный сбой перевести в `FAILED`; бесконечные retry запрещены.

### 13.6. HDR → SDR

Профиль MVP должен использовать `gpu-next` и поддерживаемый mpv tone mapping. Конкретные значения `tone-mapping`, `target-peak` и связанных параметров выбираются только по результатам визуального прототипа на HDR10-тесте.

Критерии прототипа:

- изображение не выглядит серым или выцветшим;
- светлые участки не превращаются целиком в белые пятна;
- детали в тенях различимы;
- цвета кожи не имеют очевидного зелёного или пурпурного сдвига;
- переключение на программное декодирование не меняет цветовой профиль радикально.

Параметры профиля хранятся централизованно и покрываются snapshot-тестом сформированного списка аргументов.

### 13.7. Масштабирование

| Режим UI | Поведение mpv |
|---|---|
| `Вписать` | сохранить пропорции, показать всё изображение, допускаются чёрные полосы |
| `Заполнить` | сохранить пропорции, заполнить экран, симметрично обрезать лишнее |
| `1:1` | не масштабировать видеокадр; центрировать; выходящие за экран части обрезаются |

Переход между режимами применяется без перезапуска файла и без изменения позиции.

## 14. Воспроизведение и управление

### 14.1. Поддерживаемые файлы

Обязательная проверка:

- контейнеры MKV и MP4;
- H.264/AVC;
- H.265/HEVC, включая Main 10;
- AAC, MP3, AC3; другие форматы — по поддержке сборки mpv;
- встроенные и внешние субтитры.

AVI, MOV, MPEG-TS, WebM, MPEG-2, VP9 и AV1 доступны по возможностям поставляемой сборки mpv, но для каждого формата должен существовать хотя бы один smoke-тест перед релизом.

DVD, Blu-ray, URL и сетевые потоки блокируются на уровне UI и не входят в MVP.

### 14.2. Открытие файла

1. Проверить существование, тип regular file и доступ на чтение.
2. Добавить файл в плейлист, если его там нет, либо выбрать существующую запись.
3. Получить метаданные.
4. Найти resume entry.
5. Если файл не завершён и позиция больше 30 секунд, предложить продолжить или начать сначала.
6. Подготовить дисплей и загрузить файл.
7. Дождаться `file-loaded` или ошибки не более 15 секунд.
8. Применить выбранные дорожки, масштабирование, громкость и позицию.
9. Начать воспроизведение только после успешного размещения окна на target.

### 14.3. Команды

- Play/Pause — идемпотентное изменение свойства `pause`.
- Stop — остановить текущий файл, оставить сессию вывода и чёрное внешнее окно.
- «Остановить вывод» — закрыть mpv и восстановить дисплей.
- Перемотка на ±10/±60 секунд ограничивается диапазоном `[0, duration]`.
- Drag шкалы не отправляет команды на каждый пиксель: во время drag обновляется preview времени, при отпускании отправляется один seek.
- Обновление позиции UI — 4 раза в секунду, но запись resume — не чаще одного раза в 10 секунд.
- После `eof-reached` запускается следующий элемент; после последнего плеер переходит в idle и остаётся на чёрном фоне.

### 14.4. Горячие клавиши

Горячие клавиши работают, когда активно основное окно ScreenPilot и фокус не находится в текстовом поле:

| Клавиша | Действие |
|---|---|
| `Пробел` | play/pause |
| `←` / `→` | −10 / +10 секунд |
| `Ctrl + ←` / `Ctrl + →` | −60 / +60 секунд |
| `↑` / `↓` | громкость ±5 процентных пунктов |
| `Esc` | остановить внешний вывод и восстановить конфигурацию |
| `Ctrl + O` | открыть один или несколько видеофайлов |

Глобальные системные hotkeys в MVP не регистрируются.

## 15. Метаданные и плейлист

### 15.1. Плейлист

Поддержать:

- добавление одного или нескольких файлов через диалог;
- drag-and-drop файлов;
- удаление одного или нескольких выбранных элементов;
- изменение порядка кнопками вверх/вниз и перетаскиванием;
- запуск двойным щелчком или кнопкой Play;
- переход к предыдущему и следующему элементу;
- автоматический переход к следующему;
- отсутствие зацикливания.

Дубликат определяется по `MediaFingerprint`. Повторное добавление выбирает существующую строку и показывает уведомление, но не создаёт вторую запись.

Папки и рекурсивное сканирование в MVP не поддерживаются.

### 15.2. Фоновое получение метаданных

Использовать отдельный headless mpv probe process не более одного одновременно:

- отключить видео- и аудиовывод;
- не декодировать кадры для предпросмотра;
- открыть файл, дождаться метаданных, запросить свойства и закрыть/очистить media;
- тайм-аут одного файла — 10 секунд;
- пользовательское воспроизведение всегда важнее probe;
- при старте основного воспроизведения активный probe можно завершить.

Если метаданные получить не удалось, элемент остаётся в плейлисте с состоянием `Не удалось прочитать`. Пользователь может попытаться открыть его; ошибка probe не считается окончательной ошибкой воспроизведения.

### 15.3. Отображение

Для каждого элемента показывать:

- имя;
- контейнер;
- видеокодек;
- разрешение;
- FPS;
- длительность;
- состояние текущего элемента.

Полный путь доступен в tooltip и контекстном действии `Показать в проводнике`.

## 16. Звук

### 16.1. Источник списка

Основной источник — свойство mpv `audio-device-list`, поскольку выбирать нужно устройство конкретно для процесса mpv.

Показывать:

- `Системное устройство по умолчанию`;
- все доступные render-устройства mpv;
- дружественное имя;
- внутренний ID только в диагностике.

### 16.2. Автоматическое предложение HDMI

После выбора внешнего дисплея:

1. Нормализовать friendly name, manufacturer/model и connection type дисплея.
2. Нормализовать описания аудиоустройств.
3. Повысить рейтинг устройств, содержащих название монитора/телевизора, `HDMI`, `Display Audio`, название GPU или соответствующий container ID, если он доступен без отдельной сложной COM-привязки.
4. Если кандидат один и его рейтинг однозначно выше остальных, выбрать его для mpv.
5. Если кандидатов несколько, оставить текущее устройство и предложить выбор пользователю.
6. Если кандидатов нет, оставить текущий выход и показать `HDMI-аудиовыход не найден`.

Нельзя менять Windows default endpoint. Нельзя также менять признак primary display: встроенный экран остаётся основным экраном Windows.

### 16.3. Поведение

- Диапазон громкости UI: 0–100%.
- Значение выше 100% через UI недоступно.
- Mute не уничтожает сохранённую громкость.
- При исчезновении выбранного устройства playback ставится на паузу, затем предлагается default или другой выход.
- Если mpv не умеет сменить устройство без перезапуска, сохранить позицию, перезагрузить файл на том же месте и восстановить pause/play.
- Стерео и multichannel не перекодировать принудительно; использовать возможности mpv и устройства.

### 16.4. Аудиодорожки

Показывать язык, title, codec, число каналов и default/forced flags. Если язык неизвестен, показывать `Дорожка N`.

Выбор сохраняется только для текущего файла. Между разными файлами автоматически использовать default track, если нет точного совпадения по ID в этой же media session.

## 17. Субтитры

Поддержать:

- встроенные дорожки;
- внешние `.srt`, `.ass`, `.ssa`;
- `Отключены`;
- выбор дорожки;
- ручное подключение файла;
- корректные Unicode-пути.

При добавлении внешнего файла:

1. Проверить расширение и доступ на чтение.
2. Отправить mpv `sub-add` с выбором добавленной дорожки.
3. Обновить список после события tracks changed.
4. При ошибке сохранить playback и показать сообщение без остановки видео.

Расширенные настройки шрифта, цвета, позиции, кодировки и задержки субтитров не входят в MVP.

## 18. Сохранение данных

### 18.1. Каталог приложения

```text
%LOCALAPPDATA%\ScreenPilot\
├─ settings.json
├─ resume.json
├─ recovery\
│  ├─ display-session.json
│  └─ archive\
└─ logs\
   └─ screenpilot.log
```

Кэш метаданных можно добавить после MVP. Плейлист между запусками сохранять не требуется.

### 18.2. Настройки

`settings.json` содержит:

- `schemaVersion`;
- последнюю папку;
- стабильный ID последнего target;
- ручной режим или `auto`;
- последнюю ручную пару resolution/refresh;
- scaling mode;
- audio device ID и display name;
- volume и mute;
- настройку `Приоритет плавности`;
- размер и положение основного окна;
- последний успешно использованный player profile.

Если сохранённый target или режим недоступен, приложение использует безопасный default и не пытается применить устаревшие значения.

### 18.3. Позиции просмотра

Правила:

- сохранять позицию каждые 10 секунд во время playback;
- сохранять при pause, stop, смене файла и закрытии;
- не сохранять позицию меньше 30 секунд;
- считать файл завершённым при достижении 95% длительности или если осталось меньше 120 секунд;
- для завершённого файла не предлагать продолжение;
- хранить не более 1 000 записей, удаляя старые по LRU;
- при изменении размера или времени модификации файла считать его новым.

`resume.json` не должен переписываться на каждый UI tick.

### 18.4. Надёжная запись

Для каждого JSON-файла:

1. Сериализовать в соседний `.tmp`.
2. Выполнить flush и закрыть stream.
3. Переместить с `ATOMIC_MOVE` и `REPLACE_EXISTING`.
4. Если атомарное перемещение недоступно, выполнить безопасный replace и залогировать fallback.
5. При повреждённом JSON переименовать его в `.corrupt-<timestamp>`, загрузить defaults и показать одно уведомление.

Схема каждого файла версионируется. Неизвестная более новая schema не перезаписывается автоматически.

## 19. Пользовательский интерфейс

### 19.1. Общие требования

- Тёмная тема.
- Основные операции доступны в одном основном окне.
- Макет `screen.png` задаёт визуальное направление, но не пиксельную копию.
- На ноутбуке нет видеокадров, thumbnails и живого preview.
- UI работает при 1366×768 и 1920×1080.
- Масштабирование проверяется при Windows DPI 100%, 125%, 150% и 200%.
- Минимальный размер окна задаётся так, чтобы оставались доступны Play/Pause, шкала, выбор target и `Остановить вывод`.
- При недостатке места второстепенная информация сворачивается или прокручивается; главные controls не уходят за пределы окна.
- Во время активной сессии вывода основное окно располагается на встроенном экране ноутбука; external target занят только окном видео.

### 19.2. Основная компоновка

1. Верхняя строка:
   - название ScreenPilot;
   - состояние внешнего экрана;
   - текущая топология;
   - индикатор recovery/error.
2. Центральная область:
   - имя и параметры текущего файла;
   - крупная шкала времени;
   - Previous, −10 sec, Play/Pause, +10 sec, Next;
   - volume, audio track, subtitles;
   - текстовая строка состояния.
3. Правая панель:
   - target;
   - resolution;
   - refresh;
   - auto mode;
   - scaling;
   - audio device;
   - `Воспроизвести на внешнем экране`;
   - `Остановить вывод`.
4. Нижняя область:
   - плейлист;
   - add/remove/reorder;
   - количество элементов и общая длительность.

Разделы `Экран`, `Звук`, `Плейлист`, `Настройки` могут быть панелями или диалогами, но основные controls не должны требовать постоянной навигации.

### 19.3. Состояния controls

| Условие | UI |
|---|---|
| Нет внешнего экрана | target пуст, запуск disabled, показано действие `Подключите HDMI` |
| Есть один target | выбран автоматически |
| Есть несколько target | требуется явный выбор, если сохранённый ID не найден |
| Нет файла | playback controls disabled |
| Идёт подготовка дисплея | изменяемые display controls disabled, progress indicator |
| Файл загружается | Play disabled, Stop доступен |
| Playback active | seek, volume, tracks доступны |
| Target отключён | playback paused, output window closed, выбор target активен |
| Восстановление | закрытие окна блокируется до результата или явного аварийного выхода |

### 19.4. Диалоги

Обязательные диалоги:

- подтверждение перехода в extended topology;
- продолжить просмотр / начать сначала;
- восстановить дисплеи после незавершённой сессии;
- ошибка восстановления с ручной инструкцией;
- повторная попытка software decode;
- закрытие приложения во время display preparation/restoration.

Диалоги не должны появляться за полноэкранным окном. Их owner — основное JavaFX-окно на ноутбуке.

### 19.5. Форматирование данных

- Время: `HH:MM:SS`, для коротких файлов допустимо `MM:SS`.
- FPS: до трёх знаков после запятой без потери семейства 1000/1001.
- Частота: `59,94 Гц`, `60 Гц`.
- Разрешение: `1920×1080`.
- Неизвестное значение: `—`.
- Системные пути не обрезать без tooltip с полным значением.

## 20. Ошибки и сообщения

Каждая ошибка имеет код, техническую причину, пользовательский текст и доступное действие.

| Код | Условие | Сообщение | Действие |
|---|---|---|---|
| `DSP-001` | нет внешнего экрана | `Внешний экран не найден. Подключите HDMI и обновите список.` | обновить |
| `DSP-002` | target исчез | `Внешний экран отключён. Видео поставлено на паузу.` | выбрать экран |
| `DSP-003` | topology change failed | `Windows не удалось переключить в режим «Расширить».` | повторить / открыть параметры |
| `DSP-004` | mode rejected | `Экран или драйвер не принял выбранный режим.` | автоматический режим |
| `DSP-005` | actual mode mismatch | `Windows установила другой режим. Предыдущие настройки восстановлены.` | выбрать другой режим |
| `DSP-006` | restore failed | `Не удалось полностью восстановить конфигурацию экранов.` | инструкция / повторить |
| `PLY-001` | mpv missing | `Компонент воспроизведения отсутствует или повреждён.` | переустановить |
| `PLY-002` | IPC timeout | `Видеоплеер не отвечает.` | перезапустить вывод |
| `PLY-003` | media open failed | `Не удалось открыть видеофайл.` | выбрать другой файл / детали |
| `PLY-004` | hardware decode failed | `Аппаратное декодирование недоступно. Пробуем программное.` | автоматическое действие |
| `PLY-005` | software decode failed | `Видео не удалось декодировать.` | детали |
| `PLY-006` | corrupt media | `Файл повреждён или неполный.` | другой файл |
| `AUD-001` | HDMI audio absent | `HDMI-аудиовыход не найден. Выберите другое устройство.` | открыть список |

Пользовательский текст не содержит stack trace, HRESULT или JSON mpv. Кнопка `Подробнее` показывает короткое описание, код ошибки, время и путь к логу.

## 21. Реакция на отключение HDMI

Если выбранный target пропал во время воспроизведения:

1. Не позднее чем через 2 секунды отправить pause.
2. Сохранить текущую позицию.
3. Закрыть или завершить output window/process.
4. Не переносить видео на встроенный экран.
5. Обновить список дисплеев и аудиоустройств.
6. Показать `DSP-002`.
7. Оставить плейлист и основное окно доступными.
8. Не возобновлять playback автоматически после подключения.
9. После выбора target повторно подготовить дисплей и продолжить с сохранённой позиции по команде пользователя.

Если отключение произошло во время смены режима, отменить дальнейшую подготовку и перейти к восстановлению доступной части исходной топологии.

## 22. Журналирование и диагностика

### 22.1. Логи

- Файл: `%LOCALAPPDATA%\ScreenPilot\logs\screenpilot.log`.
- UTF-8.
- Ротация: 5 файлов по 5 МБ.
- Default level: INFO.
- DEBUG включается в настройках и действует до следующего запуска, если пользователь явно не сохранил его.
- В консоль релизная версия не пишет.

На INFO записывать:

- версию приложения, ОС, Java runtime и mpv;
- обезличенную конфигурацию GPU и дисплеев;
- выбранный target и режим;
- переходы state machines;
- фактический hw decoder;
- открытие файла без полного пути, если DEBUG выключен;
- смену аудиоустройства;
- начало и результат восстановления.

На DEBUG допускается полный локальный путь. Содержимое субтитров и видеоданных не логируется.

### 22.2. Диагностический отчёт

Действие `Скопировать диагностику` формирует текст без персональных путей:

- версии;
- список дисплеев и режимов;
- состояние плеера;
- последние 100 строк лога;
- последние коды ошибок.

Архивирование и автоматическая отправка не требуются.

## 23. Безопасность и устойчивость

1. Приложение работает офлайн и не открывает listening TCP ports.
2. mpv IPC использует случайный локальный named pipe; IPC не публикуется в сети.
3. Все пути передаются через `ProcessBuilder` и JSON, а не через shell.
4. Входные файлы не изменяются.
5. Пользовательский mpv config и скрипты не загружаются.
6. Не выполнять автоматически Lua-скрипты, найденные рядом с видео.
7. Бинарники mpv проверяются по SHA-256 на этапе сборки.
8. В runtime не должно быть токенов, сетевых ключей и секретов.
9. Одновременно работает только один экземпляр ScreenPilot.
10. Single instance реализуется через file lock в `%LOCALAPPDATA%\ScreenPilot`; второй экземпляр не меняет дисплеи.
11. Все JNA callbacks и native memory удерживаются столько, сколько требуется Win32 API; освобождение handles обязательно и тестируется.

## 24. Нефункциональные требования

### 24.1. Производительность

- Время появления основного окна после запуска: до 5 секунд на эталонном ноутбуке с SSD.
- Обновление списка дисплеев после подключения/отключения: до 2 секунд.
- Отклик Play/Pause: до 300 мс без учёта первичного открытия файла.
- Перемотка локального файла: целевое время до появления корректного кадра — 2 секунды.
- UI не должен зависать более чем на 100 мс из-за I/O или Win32-вызова.
- Во время playback не создаётся второй декодирующий видеопоток.
- Probe process не запускается параллельно, если это ухудшает активное playback.

### 24.2. Стабильность

- 4 часа непрерывного воспроизведения не приводят к неограниченному росту памяти.
- 20 последовательных смен файлов не оставляют дочерние mpv-процессы.
- 10 циклов start/stop output восстанавливают исходную топологию.
- 10 подключений/отключений HDMI не завершают Java-процесс аварийно.
- Повторное событие или команда не должны нарушать состояние; use cases проектируются идемпотентно.

### 24.3. Совместимость

- Unicode в путях и именах файлов, включая кириллицу.
- Пути с пробелами и длиной более 260 символов, если их поддерживают Java и mpv на текущей Windows.
- DPI 100–200%.
- Наличие virtual display driver не должно приводить к его автоматическому выбору как внешнего физического экрана.
- RDP-сеанс показывается как неподдерживаемый режим для изменения топологии; воспроизведение без смены дисплеев можно заблокировать с понятным сообщением.

### 24.4. Доступность

- Все основные controls доступны с клавиатуры.
- Фокус видим.
- Цвет не служит единственным индикатором состояния.
- Tooltip не заменяет обязательную подпись у критичных controls.
- Иконки имеют accessible text.

## 25. Сборка и установщик

### 25.1. Gradle

Репозиторий обязан содержать Gradle Wrapper. Глобально установленный Gradle не требуется.

Обязательные команды после реализации:

```powershell
.\gradlew.bat clean test
.\gradlew.bat integrationTest
.\gradlew.bat run
.\gradlew.bat jpackage
```

Каждая команда описывается в README и должна работать из корня репозитория.

Включить:

- Java toolchain 21;
- UTF-8 для компиляции и тестов;
- JUnit Platform;
- dependency locking или verification metadata;
- reproducible archive options;
- отдельный source set/task `integrationTest`;
- отчёты тестов в стандартном `build/reports`.

### 25.2. Runtime image

`jpackage` формирует self-contained runtime. Пользовательская Java не используется.

В пакет включить:

- приложение и runtime dependencies;
- JavaFX native libraries для Windows x64;
- mpv runtime с лицензиями;
- иконку;
- `README`/license notice;
- default logging configuration.

### 25.3. EXE installer

Требования:

- тип `exe`;
- `--win-per-user-install`;
- shortcut в меню «Пуск»;
- опциональный shortcut на рабочем столе через prompt;
- стандартный каталог `%LOCALAPPDATA%\Programs\ScreenPilot` или выбранный `jpackage` per-user default;

Сборка Windows installer выполняется только на Windows. Если `jpackage` потребует WiX для выбранного типа пакета, это build-time dependency разработчика, а не пользовательская зависимость; точная версия фиксируется в README.

### 25.4. Версионирование

- Начальная версия MVP: `0.1.0`.
- SemVer.
- Версия отображается в UI и в диагностике.

| Integration | реальный mpv, тестовые media, временные каталоги | GPU желателен |
| UI smoke | запуск JavaFX, binding состояний, основные действия | Windows desktop |
| Hardware manual | дисплеи, HDMI, audio, hot unplug, DPI | реальный ноутбук и экраны |
| Installer smoke | чистая установка/обновление/удаление | Windows 10/11 VM или машина |

- классификация 23,976/24/25/29,97/30/50/59,94/60 FPS;

- preferred resolution и fallback;
- отсутствие смены при variable/unknown FPS;
- clamp seek к 0 и duration;
- playlist reorder/remove/next/end;
- state machine и запрещённые переходы;
- MediaFingerprint;
- completed/resume thresholds;
- миграция и повреждение JSON;
- recovery journal transitions;
- HDMI audio ranking;
- формирование безопасного mpv launch profile.

### 26.3. Component/integration tests

- JSON IPC request/response/event, out-of-order responses и timeout;
- mpv process crash;
- Unicode path;
- corrupted media;
- hardware decode fallback через fake player adapter;
- атомарная запись и восстановление после оборванного `.tmp`;

- закрытие всех Win32 handles;

## 27. Критерии приёмки MVP

MVP принят, если выполнены все пункты:

1. Установщик ставит ScreenPilot для текущего пользователя на эталонной Windows 10 без Java и mpv в системе.
2. Приложение запускается без прав администратора.
3. Внутренний дисплей корректно исключён из списка target.
4. Подключённый HDMI target обнаруживается максимум за 2 секунды.
5. Для target показываются текущий, preferred и подтверждённые progressive modes.
6. В extended topology ScreenPilot не меняет разрешение встроенного дисплея.
7. В clone/off режиме запрашивается подтверждение перехода в extended.
8. Автоматический алгоритм корректно выбирает тестовые частоты из раздела 12.
9. M01–M04 запускаются только на выбранном внешнем экране.
10. На ноутбуке нет видеокадров или второго decoding pipeline.
11. Работают Play/Pause, Stop, шкала, ±10/±60 секунд и clamp границ.
12. Работают `Вписать`, `Заполнить`, `1:1` без искажения пропорций.
13. Работают выбор аудиодорожки, subtitle track и внешние SRT/ASS/SSA.
14. Работает выбор HDMI audio и динамиков без изменения Windows default audio.
15. Работают добавление, удаление, reorder, Previous/Next и auto-next плейлиста.
16. Resume сохраняется и предлагает продолжение после повторного открытия.
17. При отключении HDMI playback ставится на паузу, output закрывается, Java-приложение не падает.
18. После штатной остановки исходная topology и mode восстановлены.
19. После незавершённой сессии следующий запуск предлагает recovery.
20. M04 HEVC Main 10 воспроизводится без fatal decode error.
21. M05 HDR10 на SDR-экране показывает приемлемый tone mapping.
22. При hardware decode error выполняется ровно одна попытка software fallback.
23. После закрытия приложения не остаётся `mpv.exe`.
24. `clean test`, `integrationTest` и сборка installer проходят.
25. Installer корректно удаляется; пользовательские данные сохраняются.
26. README описывает запуск, тесты, сборку, упаковку, структуру и известные ограничения.

## 28. Технический прототип — обязательный gate

До реализации полноценного UI Terra создаёт минимальный spike в отдельной ветке или каталоге `spikes/mpv-windows`.

### 28.1. Что должен доказать прототип

1. Запуск поставляемого `mpv.exe` без пользовательского config.
2. Подключение Java-клиента к JSON IPC named pipe.
3. `loadfile`, play/pause, seek и чтение позиции.
4. Вывод только на выбранный HDMI target.
5. Стабильное размещение окна после 10 повторных запусков.
6. H.264 и HEVC Main 10 на эталонном ноутбуке.
7. Фактическое аппаратное декодирование D3D11VA или документированная причина fallback.
8. HDR10 → SDR tone mapping.
9. Получение `audio-device-list` и смена HDMI/speakers.
10. Embedded и внешний subtitle.
11. Завершение mpv через Job Object при аварийном завершении контролирующего Java-процесса.

### 28.2. Артефакты

- `docs/adr/0001-video-engine.md`;
- версия и источник mpv build;
- SHA-256 всех поставляемых binaries;
- лицензии;
- фактическая командная строка;
- таблица pass/fail;
- известные ограничения;
- короткий ручной чек-лист повторения.

### 28.3. Решение gate

- Все P0 проверки прошли — продолжить с mpv process + IPC.
- Не прошёл только native HDR — продолжить с SDR tone mapping; native HDR оставить P1.
- Не работает надёжный выбор audio device или размещение target — остановиться и сравнить libmpv/VLCJ.
- Не работает HEVC Main 10 или SDR tone mapping — mpv build неприемлем; выбрать другую сборку либо движок.

## 30. Definition of Done

Задача или этап завершены, если:

- код собирается из чистого checkout через Wrapper;
- нет новых compiler warnings, которые можно устранить;
- unit/component tests проходят;
- обработаны отрицательные и граничные случаи;
- ресурсы и native handles закрываются;
- UI не выполняет блокирующие операции;

## 32. Риски

| Риск | Вероятность/влияние | Снижение |
|---|---|---|
| mpv Windows build имеет неподходящую лицензию или состав | средняя/высокое | фиксировать source, license, hash на spike |
| Нумерация mpv screens не совпадает с Windows | средняя/высокое | HWND verification + SetWindowPos, gate 10 запусков |
| HDMI audio нельзя однозначно связать с monitor | высокая/среднее | эвристика + явный выбор, не менять system default |
| Driver отклоняет refresh/mode | средняя/высокое | Enum + CDS_TEST + verify + rollback |
| Восстановление невозможно после hardware change | низкая/высокое | snapshot, database fallback, journal, ручная инструкция |
| Hardware decode нестабилен | средняя/среднее | одноразовый software fallback |
| HDR выглядит неправильно | средняя/высокое | SDR-first, visual media test, native HDR отложен |
| JNA structure layout ошибочен | средняя/высокое | сверка размеров, fixtures, тест на реальной ОС |
| JavaFX UI зависает из-за native/IPC | средняя/среднее | отдельные executors и thread rules |
| Virtual display выбран как физический | средняя/среднее | classification, явное имя и manual selection |

## 33. Вопросы, не блокирующие MVP

Эти решения принимаются после прототипа и не требуют ответа владельца до начала:

1. Конкретный поставщик Windows build mpv.
2. Точные mpv tone-mapping parameters.
3. Возможность нативного HDR в версии 0.1.0.
4. Поддержка DisplayPort/USB-C в обязательной матрице.
5. Необходимость подписывать installer сертификатом.
